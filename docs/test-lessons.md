# Xordination regression coverage and test lessons

**Owner:** xormania

This mapping describes the assertions in Xordination's deterministic tests. “Covered” means a corresponding assertion exists in the named test. It does not certify a live vendor version. “Partial” identifies the narrower assertion actually present. Test scope should follow the capabilities and failure boundaries Xordination owns.

## Durable communication and replacement

| Behavioral regression lesson | Xordination evidence | Coverage and limits |
| --- | --- | --- |
| Accepted messages and recipient receipts survive restart; reading an inbox does not consume its contents. | [test_store.py](../tests/test_store.py) `test_acceptance_survives_restart_and_inbox_is_not_consumption`; [test_end_to_end.py](../tests/test_end_to_end.py) `test_two_stdio_clients_exchange_authenticated_message_and_durable_receipt` | Covered: durable acceptance, nondestructive reads, recipient acknowledgement and retained receipts. The end-to-end case uses two actual stdio subprocesses, HTTP and SQLite; it does not involve native vendor sessions. |
| A broker reopening existing state keeps SQLite's WAL index in use, so another process's reader cannot reset it under the broker. | [test_store.py](../tests/test_store.py) `test_reopened_store_keeps_wal_index_in_use_for_other_processes`, `test_failed_reopen_releases_retained_wal_index_descriptors`, `test_second_store_in_process_cannot_release_first_stores_wal_index_lock` | Covered: a failed initialization releases the retained descriptors; after reopening, a second process cannot take the WAL-index "first connection" lock. Found when the managed launcher's read-only verifier reset the index under a restarted broker (SIGBUS); the post-open permission recheck had closed a descriptor and released the process's POSIX locks. Stores on the same path in one process share one set of retained descriptors, so another Store's open, failed open or close keeps the lock. Descriptors opened outside `Store` on these files would still carry the risk. |
| Refusing an unsupported schema leaves the newer broker's state exactly as found, including uncheckpointed WAL frames. | [test_store.py](../tests/test_store.py) `test_unknown_schema_version_is_refused_without_modification`, `test_unknown_schema_with_uncheckpointed_wal_is_refused_without_checkpoint` | Covered: a rollback-journal file keeps its exact bytes, and after a newer writer crashes with its schema only in the WAL, the refusal leaves the main file and WAL bytes unchanged, keeps the `-shm` sidecar at its size, and the newer data stays readable. The probe is read-only rather than `immutable` (which would ignore the WAL) or `nolock`; it may still rebuild the transient `-shm` index. Only POSIX file modes may change. |
| Ambiguous submission remains uncertain until the sender explicitly chooses to retry. | [test_store.py](../tests/test_store.py) `test_ambiguous_restart_requires_explicit_sender_retry`, `test_expired_claim_becomes_uncertain_without_automatic_replay`, `test_receipt_and_transport_uncertainty_remain_independent` | Covered: ambiguous delivery is retained; receipt and submission are separate facts; only explicit sender retry creates a new attempt. |
| Replacement invalidates old credentials and prevents late attempts from settling delivery for a new generation. | [test_store.py](../tests/test_store.py) `test_replacement_fences_captured_context_and_requires_recovery`, `test_stopped_participant_requires_explicit_replacement_before_recovery`, `test_delayed_retired_attempt_cannot_settle_recovered_generation` | Covered at the broker boundary: captured old credentials cannot send, claim or acknowledge for the replacement; late attempt evidence cannot settle its delivery. The shared adapter conformance scenario `test_replacement_fences_late_native_evidence` replaces the recipient between claim and native submission for the Codex, Grok and Claude channel fixtures: the old adapter's evidence is retained as late, nothing is resubmitted and the replacement binding is untouched. A real replaced Claude hook process is not exercised by these tests. |
| Recovery preserves original message intent and makes newly visible older messages discoverable. | [test_store.py](../tests/test_store.py) `test_idempotency_uses_original_intent_before_binding_resolution`, `test_recovery_of_submitted_unacknowledged_message_requires_explicit_retry`, `test_recovery_invalidates_high_water_to_cover_newly_visible_old_message` | Covered: the original destination generation is immutable; handover is explicit, and a cursor resynchronizes when older messages become visible. Recovery alone does not replay a submitted message. |
| Authorization and idempotency use stable generation identity under concurrent operations. | [test_store.py](../tests/test_store.py) `test_replacement_fences_captured_context_and_requires_recovery`, `test_authorization_binds_token_space_recipient_and_reply`, `test_concurrent_duplicate_acceptance_and_claim_have_one_owner`; [test_server.py](../tests/test_server.py) `test_replacement_after_dispatch_authentication_is_fenced_by_store_operation` | Covered: opaque generations and transaction-time token revalidation avoid mutable selection or timestamp identity. Duplicate acceptance/claim concurrency is tested, and a replacement forced between HTTP dispatch authentication and the store operation is refused as `stale_generation` for send, claim, ack and inbox without changing the message. |

## Native activity, readiness and callbacks

| Behavioral regression lesson | Xordination evidence | Coverage and limits |
| --- | --- | --- |
| Delivering a peer message during unfinished work retains the existing native session. | [test_adapters.py](../tests/test_adapters.py) `test_codex_busy_delivery_survives_held_tool_and_retains_thread`, `test_grok_busy_interject_does_not_create_new_session` | Covered with owned mock native subprocesses: held work does not block delivery, and incoming content retains the native thread/session. This establishes protocol behavior of the fixture, not actual model ingestion or token-generation interruption. |
| An old prompt response, completion or chunk cannot erase newer native activity. | [test_adapters.py](../tests/test_adapters.py) `test_grok_old_prompt_response_cannot_idle_received_newer_interjected_turn`, `test_grok_late_completion_cannot_clear_newer_activity`; Codex held-tool case above | Covered for the named schedules: after a durable receipt and newer native activity, the actual old prompt response, late old completion and old tool chunk cannot clear or replace that activity. A unit case also fences a new anonymous epoch after known completion against the original response. This does not certify every anonymous-event schedule or vendor version. |
| Original prompt completion does not prove that an interjected message was received. | [test_adapters.py](../tests/test_adapters.py) `test_grok_unacknowledged_interjection_survives_original_prompt_completion`; busy-interjection case above | Covered: the original prompt's completion leaves each unreceived interjection pending; the next message still uses interjection. Actual SQLite-backed recipient receipts and correlated recipient-generation replies clear individual barriers. A receipt from a replacement generation cannot clear the original barrier. Submission alone never invents an acknowledgement. |
| A delayed start response cannot reactivate a turn already observed complete. | [test_adapters.py](../tests/test_adapters.py) `test_codex_completed_event_before_start_response_never_reactivates_turn` | Covered for Codex startup and peer delivery: an owned mock subprocess emits start and completion before its RPC response; the response cannot reactivate the completed turn, and a late old start cannot supersede a new turn. |
| Native crashes and failed settlement never imply successful completion or automatic replay. | [test_adapters.py](../tests/test_adapters.py) `test_grok_prompt_crash_retains_uncertainty`, `test_codex_process_crash_is_uncertain_and_has_no_automatic_retry`, `test_unsettled_stale_finish_is_not_retried_natively`; conformance `test_ambiguous_submission_is_uncertain_without_retry`, `test_stale_finish_is_not_replayed` | Covered: native transport loss retains uncertainty, and a failed durable finish cannot cause an implicit second native submission. These assertions remain separate from successful receipt evidence. |
| A broker restart or transient network loss does not end a managed native session, replay ambiguous delivery or keep a replaced generation's authority. | [test_adapters.py](../tests/test_adapters.py) `test_managed_codex_session_survives_broker_restart_and_keeps_fencing`, `test_lost_finish_response_settles_once_from_durable_attempt`, `test_reconnected_finish_of_replaced_generation_stays_fenced`, `test_broker_reconnect_is_bounded_and_never_retries_broker_answers`, `test_claude_supervisor_survives_broker_outage`, `test_client_reports_dropped_broker_connection_as_connection_error` | Covered: a real broker restarted on the same state file and port under a running Codex adapter with an owned scripted native keeps the same native thread and process, delivers each message once, and a later replacement still ends the old adapter. A lost finish response settles from the durable attempt only; a generation replaced during the outage cannot settle. The outage bound is enforced and non-transient answers are not retried. The Grok adapter shares this loop but has no separate restart case; the Claude supervisor is checked with a scripted client and executable. |
| Every adapter meets the same failure contracts (AC-12). | [test_adapters.py](../tests/test_adapters.py) `AdapterConformance`, run by `CodexConformanceTests`, `GrokConformanceTests` and `ClaudeChannelConformanceTests` | Covered with one scenario set: startup failure leaves no active binding or readiness claim; transport loss after the native has read the delivery frame is uncertain with one attempt and no retry (the Codex and Grok fixtures record the frame they read before exiting, and the test asserts the native received exactly that one frame; the Claude channel stdout fails while the frame is written); a refused durable finish is never resubmitted; replacement fences late evidence; refused capabilities (attach/resume, explicit native rejection, unverified Claude channel flag) have no fallback submission or session. Each harness supplies only its fixture: managed Codex/Grok loops against the scripted natives, and the Claude MCP channel frontend after registration. A real SQLite broker records the outcomes. Vendor behavior is not exercised. |
| Channel delivery waits for fresh registration, and a successful write establishes submission only. | [test_mcp.py](../tests/test_mcp.py) `test_channel_waits_for_registration_and_reports_submission_not_receipt`, `test_channel_failed_write_is_uncertain_and_not_automatically_replayed`; [test_adapters.py](../tests/test_adapters.py) `test_claude_registration_waits_for_complete_fresh_line` | Covered locally: no claim before registration; an incomplete line is not registration; channel write is submission, not receipt; broken output is uncertain. Full Claude startup with a real hook and channel remains unverified. |
| A Claude release that omits the channel flag from `--help` is probed without a session, not rejected or assumed. | [test_adapters.py](../tests/test_adapters.py) `test_claude_doctor_accepts_listed_or_parser_accepted_channel_flag`, `test_claude_doctor_rejected_channel_flag_remains_unverified` | Covered with owned fake executables: a listed flag is supported; an unlisted flag is supported only when the option parser accepts it and stops at the missing-input refusal; an unknown-option rejection stays unverified and refuses launch before binding. Observed on Claude Code 2.1.302, whose help omits the flag. |
| Capability discovery and registration cannot certify live native communication. | [test_adapters.py](../tests/test_adapters.py) `test_missing_binary_is_not_live_certification`, `test_unverified_attach_cannot_become_fresh_session`; HTTP health reports `native_communication_verified: false` | Intentional evidence gap: there is no Xordination native fresh-challenge round trip yet. Registration and a client-only receipt cannot become a communication-readiness certificate, nor survive replacement as proof of the new native session. |

## Remaining verification work

[Behavior journeys](../tests/behavior.py) now add complete directed exchanges through owned stdio clients plus duplicate, replacement/recovery, uncertain-restart/retry and held native protocol journeys. Their frozen-manifest oracle rejects cross-run/generation/attempt evidence and missing required cases while preserving partial results. [Behavior oracle tests](../tests/test_behavior.py) exercise intended planted reds after passing controls. These remain protocol-fixture observations, not vendor model acceptance.

[Native acceptance](../scripts/testing/live.py) provides operator-invoked preparation, frozen bindings, exact source tasks and a read-only verifier requiring actual native tool observations. [Performance](../scripts/testing/benchmark.py) separates setup/work/cleanup and checks authenticated loopback workload correctness before reporting timing. [Testing guide](testing.md) describes their evidence boundaries and commands. Neither a live-validator fixture nor a broker benchmark establishes a current vendor capability.

Native fresh-challenge exchanges, response/event order where not already exercised, trace provenance, independently observed runtime settings, and process-family cleanup require their own evidence if supported. Mock subprocesses and durable broker tests establish narrower guarantees than live vendor verification.

Keep one shared broker contract suite, one shared adapter conformance suite (add a harness by supplying its fixture, not by copying scenarios) and focused adapter ordering cases. Add a regression when it protects an actual Xordination capability or failure boundary, and preserve the exact scenario in its assertions. A differently scoped test does not establish equivalent coverage.
